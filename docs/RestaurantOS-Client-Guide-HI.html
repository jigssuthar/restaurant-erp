RestaurantOS01 · Overview
The product at a glance

RestaurantOS kya karta hai?

RestaurantOS ek web-based restaurant management platform hai. Restaurant owner apna online workspace banata hai; team usmein branches, menu, tables aur customer orders manage karti hai.

Website & account

Public website, contact form, account registration, login aur password reset ke entry points.

Restaurant workspace

Dashboard, branches, categories, products, dining tables, QR links, orders, staff aur settings.

Guest QR experience

Customer table ka QR scan karke menu dekhta, items select karta aur order summary receive karta hai.

SaaS administration

Platform operator multiple restaurant accounts, configurable subscription plans aur billing status manage kar sakta hai.

Typical customer journey

Restaurant signup→Workspace setup→Menu & tables→QR print→Guest order→Team processes order
System ka purpose: restaurant ke basic dine-in operations ko ek jagah lana. Yeh guide available workflow samjhata hai; yeh accounting, inventory ya food-delivery marketplace ka claim nahi karta.

RestaurantOS04 · Operations
Manage branches, menus & tables

Core restaurant modules

Branches

Restaurant ke outlets organize karein. Branch code organization ke andar unique hota hai. Owner/manager ko apni organization ka data hi dikhai deta hai.

Categories

Customer-facing menu groups set karein. Category ko deactivate karke uske products ko guest menu se hide kiya ja sakta hai.

Products & menu

Price, cost price, category, image, description aur available/unavailable status update karein. Customer order mein product ka price server se calculate hota hai.

Dining tables

Table number/capacity aur operational status dekhein. Active orders hone par system table ko available mark karne se rokta hai.

Staff management

Owner/authorized administrator team accounts create/update karein. Staff ko branch assign karein aur sirf zaroori role dein.

Search & filters

Supported lists mein name/code, branch, status, order type ya order number se records dhoondhein. Lists paginated hain.

Table QR kahan milega?

  1. Dashboard se Dining Tables kholein.
  2. Table detail page open karein.
  3. Us table ka QR print ya download karein.
  4. Restaurant mein sahi physical table par QR card lagayein.
QR replace karna: QR rotate karne se purana link invalid ho jata hai. Naya code print karke hi table par lagayein; stale QR se guest order nahi kar payega.

Menu mein inactive categories/unavailable products nahi dikhte. Isse sold-out item ko customer se temporarily hide kiya ja sakta hai.

RestaurantOS05 · Orders & payments
From order to completion

Order management workflow

Staff dashboard se order create kar sakte hain, ya customer table QR se. Har order ke saath branch, item names, quantities aur order-time price record hota hai.

Pending→Preparing→Ready→Completed

Order ko permitted workflow ke mutabik cancel kiya ja sakta hai. Completed/cancelled orders final states hain. Paid order cancel karne ke liye refund workflow is version mein available nahi hai.

Order types

Dine-in

Dining table se linked. Staff ya table QR se create ho sakta hai.

Takeaway

Restaurant staff order enter karta hai; guest QR workflow table dine-in ke liye hai.

Delivery

Staff customer name aur delivery address enter karta hai; configured delivery fee apply hoti hai.

Payment kaise record hota hai?

Payment optionSystem behavior
CashRestaurant par payment milne ke baad staff payment status Paid karke Cash select karta hai.
CardExternal card terminal par payment ke baad staff record karta hai. RestaurantOS card terminal ko charge nahi karta.
UPIRestaurant ke UPI QR/app par payment ke baad staff UPI method select karke record karta hai.
PendingPayment baad mein lena hai to order pending rehta hai. QR dine-in order initially unpaid rehta hai.
Important distinction: Razorpay subscription checkout restaurant ke RestaurantOS plan ki payment ke liye hai. Yeh feature guest ke food order ka online payment process nahi karta.

RestaurantOS06 · Guest QR ordering
A smooth table-side experience

Customer QR se order kaise deta hai?

1

Table-specific QR scan

Guest phone camera se apne table par laga QR scan karta hai. Login ya app install ki zaroorat nahi.

2

Available menu browse

Usi branch ke active categories aur available products customer ko dikhte hain.

3

Items select karein

Quantity select/change karne par cart, selected items aur estimated total screen par update hote hain.

4

Order place karein

Optional name, phone ya notes ke saath order submit hota hai. Server availability aur current product prices verify karke total banata hai.

5

Order summary dekhein

Confirmation par order number, table, date/time, items, quantity, line totals, subtotal, tax, service charge aur total dikhte hain.

6

Restaurant mein pay karein

QR order unpaid hai; customer payment restaurant staff ko deta hai. Staff dashboard mein payment method record karta hai.

Correct table routing: Har table ka unique QR token us table ko order se link karta hai. Active menu items aur status server par dobara check hote hain; customer browser se bheja hua price accept nahi hota.

Guest ko kya chahiye?

Internet access, camera/QR scanning aur modern mobile browser. Ordering experience responsive web page hai; alag mobile app install nahi karni hoti.

Table reserved ya maintenance status mein ho to QR menu/order available nahi hota. Table occupied ho lekin active ho to additional QR order allowed hai.

Daily visibility and pricing setup

Dashboard kya dikhata hai?

Dashboard authorized user ke scope mein current database se operational snapshots dikhata hai, jaise:

Sales

Paid, non-cancelled order totals ka currency ke hisab se summary.

Orders

Order count aur status-wise breakdown.

Business setup

Organizations (platform view), branches, users, categories, products aur dining tables counts.

Dashboard accounting ledger, tax filing return, profit-and-loss statement ya inventory valuation report nahi hai.

Settings se order total kaise banta hai?

Order componentCalculationWhen it applies
SubtotalCurrent item price × quantity ka sumAll orders
TaxSubtotal × configured tax rateAll orders
Service chargeSubtotal × configured service-charge rateAll orders
Delivery feeOrganization setting ka fixed feeDelivery orders only
DiscountDiscount/coupon feature is release mein nahiNot applied
Illustrative example: ₹1,000 subtotal + 5% tax (₹50) + 2% service charge (₹20) = dine-in total ₹1,070. ₹40 configured delivery fee ke saath delivery total ₹1,110. Rates sirf example hain—apne business ke rules ke mutabik set karein.
Business responsibility: Applicable tax, tax label, customer disclosures, invoice requirements aur fee policy ko accountant/legal adviser se verify karein. Software settings tax advice nahi hain.

RestaurantOS08 · SaaS plans & billing
Multi-restaurant subscription model

Trial aur plans ka workflow

Platform par har customer restaurant ka separate workspace aur subscription record hota hai. Signup par default 30-day trial create hota hai. Paid plans platform administrator manage/publish karta hai.

Trial workspace→Plan choose→Razorpay subscription checkout→Verified payment→Active plan

Plan mein kya configure ho sakta hai?

  • Plan name, description, monthly/yearly billing interval
  • Price aur supported platform currency (current configuration)
  • Razorpay recurring plan ID
  • Maximum branches, staff, products aur dining tables (blank means unlimited)
  • Website par dikhne wale plan features aur display order

Razorpay kis kaam ke liye hai?

Razorpay RestaurantOS subscription checkout aur recurring billing ke liye use hota hai. Checkout tabhi start hoga jab deployment credentials configured hon aur Razorpay plan ka amount, currency aur interval published plan se match kare.

Customer billing screen

Restaurant owner current trial/subscription status, available plans aur recorded payment history dekhta hai; active subscription ki renewal cancel kar sakta hai.

Cancellation

Cancellation current billing period ke end par schedule hoti hai. Access period end tak rehna chahiye; gateway webhook subscription state update karta hai.

Expiry behavior: Trial/subscription expire hone par restaurant workspace aur public table QR orders block hote hain; owner billing page tak pahunchkar plan choose kar sakta hai.
Plan feature note: Branch/staff/product/table quantity limits enforce hote hain. Plan ke feature text website par display ke liye hai; har feature ke liye alag module-level on/off control is version mein abhi nahi hai.

RestaurantOS09 · Platform operations
For the RestaurantOS operator

Platform Admin ki responsibilities

Platform Admin ek trusted operator role hai, restaurant owner role se alag. Is role ka use sirf SaaS operations aur customer onboarding support ke liye hona chahiye.

Account operations

  • Restaurant organizations dekhna/manage karna.
  • Platform admin account securely create karna.
  • Restaurant users ko tenant admin ke through support dena.

Plan operations

  • Plan draft create/edit karna.
  • Razorpay par matching recurring plan banana.
  • Price/interval verify karke plan publish karna.

Billing operations

  • Deployment secrets set karna; code mein nahi.
  • Razorpay webhook endpoint configure karna.
  • Test-mode checkout, renewal, failures aur cancellation test karna.

Customer operations

  • Support contact aur escalation process dena.
  • Backups/restore procedures plan karna.
  • Privacy, terms, tax/refund policies business ke saath approve karna.

Business launch ke liye zaroori

  • Domain + HTTPS, production database, production environment/debug off.
  • Reliable outbound email for password reset aur customer support contact.
  • Razorpay test-mode validation, published plan IDs and webhook secret.
  • Privacy policy, terms, cancellation/refund policy aur tax disclosures reviewed.
  • Database backup, access control, monitoring aur recovery plan.
  • Demo records ka review; demo account/sample data ko production customers se alag rakhein.
Security: Admin password, APP_KEY, database credentials aur Razorpay API secrets sirf authorized deployment operator ke paas rahen. Client-facing PDF mein kabhi credentials na likhein.

Important operating assumptions

  • Restaurant supplies accurate menu, product prices, branch details and tax/fee settings.
  • Staff verifies actual cash/card/UPI receipt before marking an order as paid.
  • Customer QR order is dine-in and pay-at-restaurant; no food checkout gateway flow.
  • Plan prices, taxes and commercial terms are set by the platform operator; no defaults are promised.
  • Application access requires internet and an active browser/device.

RestaurantOS13 · FAQs
Common client questions · Part 1

FAQs

Q. Kya multiple restaurants is platform ko use kar sakte hain?

Haan. SaaS structure mein har restaurant ka alag organization/workspace, user scope aur subscription record hota hai.

Q. Customer QR scan karke order kare to payment kahan hoti hai?

Customer order online submit karta hai, par is workflow mein payment restaurant par hoti hai. Staff Cash, Card ya UPI method se payment record karta hai.

Q. Razorpay order payment ke liye hai?

Nahi. Current Razorpay integration RestaurantOS software subscription billing ke liye hai; restaurant food order checkout ke liye nahi.

Q. Table QR code kahan se milega?

Admin dashboard → Dining Tables → required table detail. Wahan se print/download karein. QR rotate karne par purana code kaam nahi karega.

Q. Trial ke baad kya hoga?

Trial/active subscription access expire hone par workspace aur customer QR ordering block hote hain. Owner billing page par plan choose kar sakta hai. Live paid checkout ke liye Razorpay secrets, matching plan ID aur webhook configuration chahiye.

Q. Kya subscription price pehle se fixed hai?

Nahi. Platform Admin plan price aur limits configure karta hai. Commercial price tabhi dikhni/checkout honi chahiye jab plan publish ho aur Razorpay recurring plan matching ho.
